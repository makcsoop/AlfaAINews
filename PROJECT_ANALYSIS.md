## Кратко

Проект большой (~18,9 тыс. строк Python в `backend/`, ~1,8 тыс. строк TSX/TS), дисциплинированный: линтер, типы и тесты зелёные, инварианты в основном закреплены кодом (белый список моделей, `data_block`, `company_id` только из сессии, SSRF-защита вставки). Главные проблемы лежат **на стыках модулей**, а не внутри них:
1. конвейер может опубликовать карточку, которая **не прошла проверку кодом**, со статусом `published`;
2. деградировавший разбор кешируется как успешный на 24 ч;
3. материал, который вставила одна компания (`/analyze`), попадает в общие сюжеты и **виден в ленте других компаний**, а служебные эндпоинты с полными текстами доступны **без сессии**.

## 4. Слабые места и риски (не баги)

- **Производительность источника из БД.** `DbDataSource.stories()`/`event_facts()`/`bank_positions()`/`market_knowledge()` читают таблицы целиком без окна (`backend/agents/tools/db_source.py:68-84`). За один глубокий разбор их перечитывают несколько шагов (`steps.py`: `facts_ready`, `_score` ×2, `quick_step`, `card_step`, `card_verify_step`), `raw_items` (3000 строк с полным текстом) — минимум дважды. `/ask` на каждый вопрос читает все сюжеты, факты и позиции. Лента досчитывается раз в 5 минут по всем сюжетам за всю историю для каждой пары «компания × роль».
- **Лимит 3000 `raw_items`** (`db_source.py:28`): для сюжетов старше окна быстрые карточки и проверка цитат (`annotate_card`) теряют тексты материалов, и `evidence.verified` становится ложно-отрицательным.
- **Синхронная БД в async-воркере сбора** (`backend/ingest/run.py:23-58`): `engine.begin()` внутри корутин блокирует цикл событий для всех лент и Telegram. Падение подключения Telethon в `async with client` выходит из `gather` и роняет весь воркер (спасает только `restart: unless-stopped`).
- **Бюджет проверяется неатомарно** (`check`, потом `record`): параллельные процессы (backend + ingest + `/ask`) могут слегка превысить лимит. По умолчанию лимит 300 ₽ из 500, запас есть.
- **Гонка `/analyze` и `rebuild`** в разных процессах: история присоединения вставки и `item_ids` сюжета могут потерять обновление (read-modify-write `stories.data` без блокировки, `paste.py:191-202` vs `cluster.py:357-376`).
- **Демо-вход:** любой посетитель получает сессию любой демо-компании с любой ролью (`routes.py:91-112`); cookie без `secure`. Для демо приемлемо, для пилота — нет.
- **Кеш разбора без версии промпта и модели** (`pipeline.py:88-90`): после правки промптов аналитиков старые разборы живут до 24 ч.
- **13 тестов БД** пропускаются без Postgres, и проверки, которые касаются B3, B4 и B9, ни одним тестом не покрыты. CI нет, поэтому `main` «всегда запускается» только на доверии.
