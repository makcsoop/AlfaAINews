## 1. Вопрос-ответ: на бессмыслицу отвечает пересказом досье — ПОДТВЕРЖДЕНА

### Воспроизведение

```bash
cd /private/tmp/claude-501/-Users-macbook-Desktop-PET-PROJECT-AlfaAINews/c57f7c4b-393e-4ad0-bedf-c2824f23bb87/scratchpad/live_repro

./ask_check.sh "Как сохранение ставки 14% отразится на стоимости наших кредитов?" "Кто наши основные поставщики и насколько мы от них зависим?"
```

Карточка `card_st_619a48fc9531_U_DEMO_BORROWER_cfo`. Результаты сохранены в `ask_nonsense.out` и `ask_normal.out`.

| Вопрос | status | Ответ |
|---|---|---|
| «ашгрывшоп» | ok | 4 позиции ЦМИ: «Альфа-Банк ожидает сохранения ключевой ставки на уровне 14,0%…», «…12,0% к концу 2027…» и т. д. Ответ из кеша: тот же вопрос пользователь задал в 18:06, `cached=True`, 0 ₽ |
| «ывапролджэ хцук» (новый, не из кеша) | ok | тот же пересказ из 4 позиций ЦМИ, 462 токена ответа |
| «ну и?» | ok | пересказ: решение ЦБ, 3 позиции ЦМИ, вывод про стоимость заёмного капитала |
| «что делаешь?» / «какая погода?» / «рецепт борща» | ok | «В данных по вашей компании и в материалах сюжета ответа на этот вопрос нет.» Это лучше, но всё равно не «не понял вопрос» и не «уточните» |
| про ставку и кредиты (нормальный) | ok | по делу: 2 позиции ЦМИ и 2 вывода |
| про поставщиков (нормальный) | ok | по делу: доли 35% и 12%, HHI 0,16, ОКВЭД; вызван `get_counterparties` |

На очевидно не относящиеся к теме вопросы модель обычно отвечает пустым `statements`. На набор букв и короткие реплики без смысла она «отвечает» содержимым досье: оно всегда есть, а промпт не запрещает так делать.

### Причины

1. **В промпте нет правила для непонятного или постороннего вопроса.** `prompts/qa.md:12`, правило 2, говорит только «Нет данных для ответа — так и напиши». Набор букв — это не «нет данных», поэтому модель перечисляет досье: правило 3 «каждое утверждение со ссылкой» она соблюдает формально.
2. **Код выбрасывает свободный `answer` модели и собирает ответ только из утверждений.** `backend/agents/qa.py:471-476`: `kept = verify_statements(...)`, затем `answer = " ".join(s.text for s in kept)`. Даже если модель напишет в `answer` «Не понял вопрос», но приложит утверждения, пользователь увидит пересказ. Если утверждений нет, он увидит `NO_DATA_TEXT` (`qa.py:47`), а не просьбу уточнить.
3. **В схеме ответа нет поля, по которому код понял бы, что вопрос не понят.** `QAAnswer` (`qa.py:62-69`) содержит только `answer`, `refs`, `statements`.
4. **Проверка ответа не смотрит, связано ли утверждение с вопросом.** `verify_statements` (`qa.py:393-419`) проверяет ссылки, метки и числа, но не связь с вопросом. Поэтому верные, но посторонние утверждения проходят.
5. **До модели нет проверки кодом.** Вопрос «ашгрывшоп» идёт в DeepSeek (≈0,035 ₽), хотя его можно отсечь бесплатно. `answer_question` (`qa.py:438-450`) отсекает только чужую компанию и инъекцию.
6. Ответ кешируется по хешу промпта (`backend/llm/client.py:503`), поэтому повторный такой же вопрос снова получит пересказ, только уже за 0 ₽.

### Исправление (Р3)

- В `QAAnswer` добавить `intent: Literal["answer", "unclear", "off_topic"] = "answer"`.
- `prompts/qa.md`: добавить правило 11 и поднять `prompt_version` до 2. Текст правила: «Если вопрос непонятен (набор символов, обрывок, реплика без вопроса: „ну и?“, „ок“) — `intent: "unclear"`. Если он не про событие, компанию или её финансы (погода, рецепты, „что делаешь?“) — `intent: "off_topic"`. В обоих случаях `statements` пустой. Не пересказывай досье, если вопрос не задан.»
- `qa.py` после `res = client.call(...)`: если `value.intent != "answer"`, вернуть `CLARIFY_TEXT` («Не понял вопрос. Уточните, пожалуйста, что именно вас интересует о событии или о вашей компании, например: „как это повлияет на наши кредиты?“») или `OFF_TOPIC_TEXT` («Я отвечаю только на вопросы о событии и о вашей компании…»). Статус — `ok` либо новый `unclear`. Новый статус потребует расширить `AskResponse.status` (`backend/api/routes.py:88`) и `frontend/src/types.ts:194`: это запрос Р2 в HANDOFFS.
- Бесплатный фильтр до модели, `is_gibberish(question)`: меньше половины слов из ≥2 букв найдено в словаре Natasha (`MorphVocab`, pymorphy2 уже в зависимостях), либо в вопросе нет ни одной буквы. `gibberish_check.py` показывает: «ашгрывшоп» даёт 0 из 1 известных слов, нормальные вопросы — 8 из 8, «ывапролджэ хцук» — 1 из 2 (pymorphy знает «хцук»). Поэтому порог нужен «< 0,5», а пограничные случаи остаются за `intent` модели. Короткие «ну и?», «ок» на фильтре не ловятся: их тоже решает `intent`.
- Необязательно, но полезно: если `intent == "answer"` и среди сохранённых утверждений нет ни одного, у которого основы слов пересекаются с основами вопроса (есть `_stems` в `backend/cards/build.py`), не склеивать пересказ, а вернуть `CLARIFY_TEXT`.

### Тесты (`tests/test_qa.py`, `LLM_MODE=fixture`)

## 2б. Фикстура «ЦБ сохранил ставку 14%» (11.09) в живой ленте — ПОДТВЕРЖДЕНА

### Воспроизведение

```bash
./feed_and_card_check.sh   # из каталога live_repro
psql postgresql://newsai@localhost:55432/newsai -c "select id, first_seen, last_seen from stories where last_seen < now()-interval '72 hours'"
```

В ленте есть `card_st_2026-09-11_keyrate_U_DEMO_BORROWER_cfo`: stage fast, score 0,086, **freshness 0,15 (нижняя граница)**. Он стоит рядом с живым `st_619a48fc9531` («… 14,00% годовых (23.10.2026)»). Кроме фикстуры, в таблице `stories` ещё 7 сюжетов с `last_seen` 22.10, то есть старше окна. Они тоже допускаются в ленту, сейчас их просто отсекает порог значимости.

### Причины

1. **Фикстура заливается в живую БД.** `backend/db/demo.py:103`: `_case()` всегда вызывает `load_fixtures(conn)`. `docker-compose.yml:45`: сервис `init` запускается с `--load-fixtures`. `load_fixtures` (`backend/db/init.py:52-110`) делает upsert сюжета, 2 `raw_items`, `event_facts` и 5 позиций ЦМИ фикстуры. Зона Р1.
2. **Пересборка сюжетов фикстуру не трогает.** `rebuild` (`backend/stories/cluster.py:289-293`, `:359-361`) работает с материалами и сюжетами окна 72 ч. Сюжет от 11.09 никогда не попадает в `old_ids` и живёт вечно. То же с любыми сюжетами, у которых `first_seen` старше окна.
3. **Источник инструментов отдаёт все сюжеты без окна.** `backend/agents/tools/db_source.py:81-82`: `SELECT data FROM stories`. Лента перебирает их все: `backend/api/store.py:316`, `for story in self._src().stories()`. Зона Р3.
4. **Свежесть не опускается ниже 0,15.** `config/scoring.yaml:46-48` (`half_life_hours: 48`, `floor: 0.15`), `backend/ranking/score.py:126-129`. Сюжет 44-дневной давности получает ×0,15 вместо ≈0 и проходит `feed.min_score: 0.05` (`scoring.yaml:148`). Зона Р2.

### Исправление: живая лента без фикстуры, тесты и демо на фикстуре сохраняются

- **Р3, главный и безопасный для тестов вариант: окно ленты в `PipelineCardStore._scan`** (`backend/api/store.py:316`). Если источник — БД (`TOOL_SOURCE=db`, то есть `self._explicit_source is None` и `_src()` вернул `DbDataSource`), пропускать сюжеты с `story.last_seen < now − FEED_WINDOW_H`. `FEED_WINDOW_H` брать из `scoring.yaml: feed.max_age_hours` (это запрос Р2), по умолчанию 72. Тесты и демо на фикстуре идут через `FixtureDataSource` или `ctx.fixture_mode`, где «сейчас» — это `story.last_seen` (`store.py:286`), поэтому фильтр их не задевает. Личные вставки (`/analyze`) свежие и проходят окно. Фильтр в самом `DbDataSource.stories()` не подходит: `tests/test_tools_db.py:54` сравнивает `db.stories() == fx.stories()` на залитой фикстуре и сломается. Если очень нужно фильтровать в источнике, пусть это будет отдельный параметр `stories(since=...)`, по умолчанию без окна.
- **Р1: не заливать фикстуру в живую базу.** Убрать `load_fixtures(conn)` из `demo._case` (`demo.py:103`) или оставить его за флагом `--with-fixture`. В `docker-compose.yml:45` оставить `--load-fixtures` только для фикстурного стенда. Добавить `python -m backend.db.init --drop-fixtures`: удаляет по id из `fixtures/rate_14/bundle.json` сюжет, `raw_items` и `event_facts`. С позициями ЦМИ осторожнее, см. ниже. Тесты `tests/test_db.py:118`, `:148` и `tests/test_tools_db.py` вызывают `load_fixtures` сами и не пострадают.
- **Р2 (по желанию):** применять `floor` свежести только внутри окна ленты, чтобы старые сюжеты не держались на нижней границе.

**Попутный риск (Р1), не удалось проверить:** `load_fixtures` делает upsert 5 позиций ЦМИ фикстуры (`cmi_keyrate_2026_09#p1#c1..c4`, `cmi_macro_1h26#p1#c1`) в живой реестр `bank_positions`. Сейчас в реестре 14 строк документа `cmi_keyrate_2026_09`. Совпадают ли тезисы фикстуры с настоящими (`#p1#r…`), не проверял. Если нет — в живые карточки могут попасть синтетические «позиции банка». При `--drop-fixtures` удалять только id `…#c…`, которых нет в снимке `data/snapshot/bank_positions.json.gz`.

## 4. Стоимость вопрос-ответа: `/trace/{id}/cost` → not_found; 0 ₽ во фронте — ПОДТВЕРЖДЕНА

### Воспроизведение

```bash

# → trace_id: 6f80a548…; GET /trace/6f80a548…/cost -> {"error":{"code":"not_found","message":"Трассировка не найдена",...}}

```

Для всех 8 вопросов `/cost` вернул `not_found`, хотя в журнале вызовов каждый trace_id записан.

### Причины

1. **/ask не сохраняет трассу.** `backend/api/routes.py:275-284`: после `answer_question` ответ сразу отдаётся, `RunTrace` не создаётся. `trace_cost` (`routes.py:240-243`) ищет только в `store.get_trace` (`backend/api/store.py:670`), а там лежат только трассы конвейера (`_add_trace`, `store.py:394`). Публичного метода положить трассу в протокол `CardStore` (`store.py:42-57`) нет.
2. **В ответе /ask нет стоимости.** `AskResponse` (`routes.py:83-88`) не содержит `cost_rub`. Фронт `AskPanel` (`frontend/src/components/AskPanel.tsx:91-106`) показывает только ответ и «Основано на». Ни ₽, ни ссылки на трассу нет: стоимость ответа пользователь не видит вообще.

### Откуда пользователь мог видеть «0 ₽»

- **Ответ из кеша LLM стоит 0.** `backend/llm/client.py:503-507` при попадании в кеш пишет `cost=0.0, cached=True`. Вчера, по `data/llm_journal/2026-10-24.jsonl`, **25 из 57 трасс целиком состояли из вызовов из кеша**. Сегодня у `1aca3b71` планировщик из кеша (0 ₽), «ашгрывшоп» второй раз — 0 ₽. `TraceView` в шапке показывает `Стоимость разбора: 0 ₽` (`frontend/src/components/TraceView.tsx:123`) и «Вызовов моделей: 4», а пометка «(кеш)» стоит только в строке таблицы вызовов (`TraceView.tsx:222`). Пользователь видит «4 вызова — 0 ₽».
- **Округление.** `rub()` форматирует с `maximumFractionDigits: 2` (`TraceView.tsx:64`, `RunsView.tsx:16`). Вызов QA стоит 0,006–0,009 ₽ (сегодня: «что делаешь?» — 0,0089, «рецепт борща» — 0,0062), то есть «0,01 ₽». Всё дешевле 0,005 ₽ показывается как «0 ₽».
- **Журнал разборов.** `_log_run` (`store.py:500-507`) пишет `cost_rub=0.0`, если трассы нет: сбой до первого вызова. В `RunsView` это «0 ₽».
- Быстрые карточки (19 из 21) не имеют `trace_id`, кнопки «как получено» у них нет. Это не «0 ₽», но стоимости тоже не видно.

### Исправление

- **Р3, `routes.py` /ask:** после `answer_question` собрать
  `RunTrace(run_id=trace_id, story_id=card.event.story_id if card else "", company_id=session.company_id, steps=[f"qa:{status}", *tools_used], llm_calls=client.journal.to_llm_calls(trace_id), cost_rub=sum(...), started_at=..., finished_at=now)`

Принадлежность проверяется по `company_id`, как и сейчас. Отказы без модели тоже сохранять, со стоимостью 0 и шагом `qa:refused`.

- **Р2, фронт:** в `AskPanel` под ответом выводить «≈0,02 ₽ · из кеша» и ссылку на `TraceView`. В `rub()` для значений меньше 0,01 показывать «<0,01 ₽» вместо «0 ₽». В шапке `TraceView`, если все вызовы `cached`, писать «0 ₽ — из кеша» и, при наличии, исходную стоимость.
