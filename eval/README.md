# eval

Оценка качества: разметка пар «сюжет × клиент» (`labeling/`), метрики отбора и интерпретации, отчёт качества.
Инструмент разметки — Разработчик 1 (день 3), метрики — по разделу «Метрики» финальной архитектуры.

## Разметка 60 пар в Excel

ТЗ для разметчиков — документ «ТЗ: разметка 60 пар «новость × компания»» (шкала 0–3, канал, знак, правила).

1. Пары и файлы: `uv run python eval/labeling/make_pairs.py --labelers anna,ivan,olga` → `data/labeling/razmetka_<имя>.xlsx`
   (папка в .gitignore — в файлах профили компаний кейса). 6 компаний кейса × 10 сюжетов за последние 72 ч,
   отбор пулом: 4 лучших по системе, 3 по бейзлайну, 3 случайных; 10 пар общие у всех, остальные поровну.
   Пары пишутся и в `label_pairs` — их же показывает `/labeling`. Партию с метками скрипт не перезаписывает.
2. Разметчики заполняют жёлтые колонки и возвращают файлы.
3. Импорт: `uv run python eval/labeling/import_labels.py data/labeling/razmetka_*.xlsx [--db]` — проверяет
   строки, пишет `data/labeling/labels-oct-60.csv` (формат `/labeling/export.csv`), считает согласие
   (`reports/agreement.md`) и метрики (`reports/metrics.md`). `--db` — метки ещё и в таблицу `labels`.

Метрики берут сюжеты из базы по `story_id`: до импорта не пересобирайте сюжеты (новая склейка может сменить id).

## Как посчитать метрики (Р2)

1. Разметить пары на `/labeling` и скачать `/labeling/export.csv`.
2. Согласие разметчиков на общих парах: `uv run python -m backend.eval.agreement labels-oct-60.csv`.
3. nDCG@5 и precision@5 против бейзлайна «свежесть + вес источника», пропуски по покрытым и непокрытым
   отраслям: `uv run python -m backend.eval.metrics labels-oct-60.csv` (нужна база Р1) → `reports/metrics.md`.
