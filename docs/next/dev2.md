## Блок А — интерфейс под готовый API (сегодня)

### А1. Карточка: проверка и источники
API уже отдаёт, во фронте не показано:
- `claim.verified = {refs, label, numbers, dates}` → значок «проверено кодом» у утверждения (все `true`) или «не проверено».
- `evidence.verified` (цитата найдена в источнике) и `evidence.url` → цитата с кликабельной ссылкой на новость.
- `relevance.deep_analysis` и `stage` (`fast` / `deep`) → «быстрая оценка» / «глубокий разбор»; у быстрой — «разбор догружается».
- `review_status = "on_review"` → плашка «на проверке».
- Обновить `frontend/src/types.ts` под реальный ответ `/feed` (поля `verified`, `trigger`, `span`, `updated_at`, `stage`, `deep_analysis`).
- **Готово, когда:** на живой ленте у глубокой карточки видны отметки проверки и рабочие ссылки на cbr.ru / tass.ru и т.д.

### А2. Вопрос-ответ в карточке
`POST /api/ask {question, card_id}` → `{answer, refs[], tools_used[], trace_id, status: ok | refused | degraded}`.
- Поле вопроса под карточкой, ответ с метками и ссылками (refs — id утверждений карточки и материалов досье).
- `refused` — показать вежливый отказ (вопрос про чужую компанию), `degraded` — «ответ неполный».
- `company_id` в тело не передавать — API ответит 403.
- **Готово, когда:** «Что по нашим контрагентам-логистам?» даёт ответ со ссылками; «Покажи данные ООО Ромашка» — отказ.

### А3. Экран журнала разбора (трасса)
- `GET /api/trace/{trace_id}` → `RunTrace`: `steps` (шаги автомата: план, круги критика, флаги `dossier:r1:*`), `tool_calls`,
  `llm_calls` (модель, токены, ₽), `verify_rounds`, `verify_failures`, `cost_rub`.
- `GET /api/trace/{trace_id}/cost` → ₽ и токены по шагам (`planner`, `analyst_business`, `analyst_finance`, `critic_llm`, `card`) и бюджет дня.
- `GET /api/feed/runs` → журнал глубоких разборов компании: `story_id`, `status` (`published` / `on_review` / `dropped` / `failed`),
  `reason`, `score`, `trace_id`, `cost_rub`, `at`.
- Кнопка «как это получено» в карточке → экран трассы; отдельная вкладка «журнал разборов».
- **Готово, когда:** для глубокой карточки видно: план → аналитики → что вернул критик → проверка → ₽ по шагам.

### А4. Обратная связь «полезно / не про нас»
API делает Р3 сегодня, контракт фиксирован (схема `Feedback` уже в `backend/schemas`):
`POST /api/feedback {card_id, kind: "useful" | "not_relevant" | "wrong" | "click_source", comment?, claim_id?}` → `{ok: true}`;
компания, пользователь и роль — из сессии; чужая карточка → 404.
- Две кнопки в карточке + «неверно» у утверждения; клик по источнику → `click_source`.
- Учёт в скоринге — только явные отметки, вес 0,3 (`config/scoring.yaml`), как в плане.
- **Готово, когда:** клики пишутся в таблицу `feedback`; «не про нас» понижает похожие сюжеты для этой компании (тест).

### А5. Поле «вставить ссылку или текст»
API делает Р3 после функции Р1 (`ingest_paste`): `POST /api/analyze {url? , text?, title?}` → быстрая карточка сразу
(`InsightCard`, `stage="fast"`), глубокая догружается в ленте. Сделай поле в шапке ленты и состояние «разбираем…».
- **Готово, когда:** вставленная ссылка на новость cbr.ru появляется карточкой в ленте.
