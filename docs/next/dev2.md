## 3. Интерфейс: довести до демо

Проверь каждый пункт руками на живой базе, на ширине 1280 и 390 px:
- **Ошибки API** (`{error: {code, message, trace_id}}`): 401 → тихий повторный вход; 403 и 404 → понятный текст; 429 → «слишком часто,
  попробуйте через минуту»; 503 у `/analyze` → текст из `message`; 400 у `/analyze` → текст ошибки под полем вставки.
- **Пустые состояния:** пустая лента («новостей для вас пока нет»), идущий разбор («разбор догружается»), пустой журнал разборов.
- **Карточка:** длинный заголовок не ломает вёрстку; у быстрой карточки пометка «быстрая оценка»; при `review_status = on_review` —
  плашка «на проверке»; если ожиданий нет («нет данных»), пустую колонку сюрприза лучше скрыть, чтобы не выглядело ошибкой.
- **Вставка:** после успешной вставки карточка появляется в ленте и открывается; повторная вставка того же текста не дублирует карточку.
- **Вопрос-ответ:** статусы `refused` (для чужой компании и для попытки сменить правила бэкенд присылает разные тексты — просто показать)
  и `degraded`.
- **Узкий экран:** таблицы трассы прокручиваются внутри, страница целиком — нет.

**Готово, когда** чек-лист пройден, `npm run build` без предупреждений TS, есть скриншоты главных экранов для слайдов.
