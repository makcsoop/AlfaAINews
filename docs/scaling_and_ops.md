# Масштабирование и сопровождение

Как добавить отрасль, тип клиента, источник, модель и обзор ЦМИ, как сервис работает каждый день и что делать,
когда что-то сломалось. Почти всё расширяется конфигами: код меняется, только когда нужен новый вид данных.

Связанные документы: [архитектура](architecture.md), [мониторинг качества](monitoring.md),
[безопасность](security.md), [контракты данных](contracts.md).

## Почему затраты растут с числом отраслей, а не клиентов

Сюжет разбирается моделями один раз на пару «сюжет × отрасль × версия сюжета» (`backend/agents/steps.py`,
кеш `AnalysisCache`). Под конкретного клиента и роль код подставляет знак и вклад каждого канала
(`backend/ranking/score.py`) — без вызовов модели. Карточку пишет модель, но по готовому разбору отрасли.

| Что растёт | Как растут затраты |
|---|---|
| Клиенты одной отрасли | почти не растут: разбор отрасли общий, персонализация — кодом |
| Отрасли | линейно: ≈ 0,3–0,4 ₽ на глубокий разбор и карточку (`reports/budget.md`) |
| Поток новостей | только сбор, склейка и правила (без модели); модель — для топ-K пар по бюджету |

Сколько пар разбирать за день, решает `config/scoring.yaml`, раздел `deep`: доля остатка бюджета, цена пары,
потолок `k_max`. При 70% дневного лимита K вдвое меньше и порог выше, при 90% — только быстрые карточки.

## Новая отрасль

Матрица `config/channels_matrix.yaml` — строки ОКВЭД → чувствительность к 30 каналам. На 25.10 строки есть
для 52 двузначных кодов (и подотраслей 46.71, 47.30), это **91,5% компаний кейса** (78 215 из 85 525).

| 93 | спорт, отдых и развлечения | 770 | средний |
| 82 | административная деятельность, поддержка бизнеса | 742 | средний |

| 60 | теле- и радиовещание | 365 | низкий |
| 59 | кино, видео и звукозапись | 364 | низкий |

Пересчитать: строки `data/case/df_Uid_data_hack.csv` (разделитель `;`, колонка `MAINOKVED_CODE`) против ключей
`okved:` матрицы.

Компания без строки отрасли всё равно получает ленту: по продуктам банка, ВЭД, контрагентам из графа платежей
и общим факторам — но без отраслевых каналов.

Шаги:
1. Строка в `okved:` — каналы и знак чувствительности от −1 до 1 (что получает компания при росте фактора).
   Подотрасль — ключ длиннее двух цифр (`"46.71"`), она добавляется поверх строки отрасли.
2. При необходимости — связи в `sector_links:` (соседние отрасли, вес 0–1).
3. При необходимости — шаблон плана разбора в `backend/agents/plan_templates.yaml` (иначе работает `default`).
4. Проверка: `uv run pytest -q tests/test_scoring.py tests/test_profile.py`, затем разметка 10–15 пар новой
   отрасли и `backend.eval.metrics` ([мониторинг](monitoring.md)).

## Новый тип события

`config/event_types.yaml`: каналы, приор воздействия (`prior`), шаблоны распознавания (`patterns`),
подсказки направления фактора (`direction_hints`). План разбора — шаблон в `plan_templates.yaml` или `default`.
Типы, которые касаются отдельных отраслей (санкции, пошлины, господдержка), — в `prior_unscoped_types`
(`scoring.yaml`): без названных отраслей их вклад ослабляется. После правки правил — пересчитать факты:
`uv run python -m backend.extract.run --all --force` (без модели, бесплатно).

## Новый тип клиента или роль

- Архетип клиента — `config/archetypes.yaml` (подбор компаний кейса под демо) и витрина входа
  `config/demo_companies.yaml` (какие компании можно выбрать; вход в остальные — 403).
- Роль — акценты каналов в `config/scoring.yaml` (`roles:`) и акцент текста в `backend/cards/prompt.py`
  (`ROLE_FOCUS`). Новое значение роли — в `UserRole` (`backend/schemas/common.py`) вместе с фикстурами.

## Новый источник

1. Запись в `config/sources.yaml`: `kind` (rss, telegram, api), `tier` 0–3, `weight`, `official`,
   `poll_seconds`, `full_text` (feed, fetch, none — права на текст), `is_partial` для пейволла, `publisher`
   (ленты одного издателя — один независимый источник: сайт и Telegram одного издания).
2. Проверка: `uv run pytest -q tests/test_ingest.py`, затем `uv run python -m backend.ingest.run --once --source <id>`.
3. Вес источника со временем уточняется отметками пользователей (`backend/ingest/source_weights.py`,
   таблица `source_weights`): стартовое значение — из `sources.yaml`.

## Новая модель

`config/models.yaml`: модель (цены за миллион токенов в ₽, лимиты) и шаги (`steps:` — модель, запасная модель
другого семейства, бюджетная группа, `max_tokens`). Разрешены только модели из списка в `CLAUDE.md`
(инвариант 2). Все вызовы — через `backend/llm/client.py`: валидация Pydantic, один повтор, запасная модель,
потом шаблон. Проверка: `uv run python -m backend.llm.probe` (один дешёвый вызов на модель) и
`uv run pytest -q tests/test_llm_client.py`.

## Новые обзоры ЦМИ

1. Документ в `config/bank_docs.yaml` и PDF в `data/bank/pdf/`.
2. Извлечение позиций — `backend/bank/positions.py` (реестр, шаг `bank_registry`, Kimi-K2.6).
3. У каждой позиции `valid_until` и, если вышел новый обзор, `superseded_by`. Позиции, срок которых истёк к дате
   события, в карточку как текущие не попадают: инструмент их не отдаёт, промпт карточки их не видит,
   проверка кодом даёт `bank_view_expired` (перегенерация, потом шаблон).

## Ежедневная работа

| Что | Как часто | Где |
|---|---|---|
| Сбор RSS и Telegram | раз в `poll_seconds` (2–10 мин) | воркер `ingest` (`python -m backend.ingest.run`) |
| Склейка сюжетов и факты (правила) | раз в 5 мин | тот же воркер (`stories_forever`) |
| Лента клиента сверяется с базой | раз в `FEED_REFRESH_S` (60 с) | API (`backend/api/store.py`) |
| Глубокий разбор | в фоне, не больше `FEED_DEEP_PER_REQUEST` в очереди ленты | API, фоновый поток |
| Прогрев демо-кеша | перед показом | `scripts/warm_demo_cache.py` |

### Бюджет моделей

- Дневной лимит — `LLM_DAILY_BUDGET_RUB` (по умолчанию 300 ₽; общий ключ — 500 ₽/день), архив знаний — отдельный
  потолок `LLM_ARCHIVE_DAILY_CAP_RUB`. Режимы 70% и 90% — см. выше.
- Итог по шагам и моделям: `uv run python -m backend.llm.report` → `reports/budget.md`.
- В трассе карточки («Как это получено») — ₽ по шагам и экономия на кешированных ответах.

### Журналы

| Журнал | Где |
|---|---|
| Вызовы моделей (шаг, модель, токены, ₽, хеши, проверка) | `data/llm_journal/*.jsonl` (`LLM_JOURNAL_DIR`) |
| Попытки доступа к чужой компании | `data/security_audit/*.jsonl` |
| Глубокие разборы ленты | `GET /feed/runs` (в памяти процесса) |
| Отсев материалов с причиной | таблица `raw_items`, поле `dropped_reason` |

### Кеш

- Ответы моделей — кеш по хешу запроса (`LLM_CACHE_DIR`, `data/llm_cache`).
- Разборы отраслей, карточки и трассы — `CACHE_BACKEND=redis` (TTL `CACHE_TTL_S`, 24 ч); без Redis — память
  процесса, которая пропадает при перезапуске.
- Карточки ленты живут в памяти процесса API. Для нескольких реплик API нужен Redis (общий кеш карточек),
  иначе каждая реплика разбирает сама.

### Ротация ключей

- `SESSION_SECRET` — сменить в `.env` и перезапустить API: все сессии станут недействительны, пользователи
  войдут заново. Сгенерировать: `openssl rand -hex 32`.
- `LLM_API_KEY` — сменить в `.env`, перезапустить `api` и `ingest`; проверить `uv run python -m backend.llm.probe`.
- Ключи и сессии Telegram — только в переменных окружения (инвариант 9).

## Что делать, если…

| Ситуация | Что видно | Что делать |
|---|---|---|
| Упал провайдер моделей | в трассе запасная модель или шаблон, «на проверке» | ничего срочного: клиент идёт по цепочке запасных; проверить `backend.llm.probe`, при долгом сбое — `LLM_API_BASE_FALLBACK` |
| Кончился бюджет дня | только быстрые карточки, «глубокий разбор ещё не готов» | дождаться следующего дня или поднять лимит; проверить `reports/budget.md`, какой шаг съел бюджет |
| Сюжеты перестали склеиваться | в ленте дубли одной новости | лог воркера `сюжеты: {…}`; порог `SIM_THRESHOLD` в `backend/stories/cluster.py`; `docs/cluster_threshold.md` |
| Новых новостей нет | последний сюжет давно | лог воркера `ingest`: недоступные ленты (HTTP 5xx) пропускаются, остальные работают |
| У позиции ЦМИ истёк срок | в карточке нет мнения банка | загрузить новый обзор (раздел «Новые обзоры ЦМИ») |
| Лента не обновляется | новые сюжеты есть в базе, но не в ленте | `FEED_REFRESH_S` не меньше 0; перезапуск API пересобирает ленты |
| Фоновые разборы мешают | — | `FEED_BACKGROUND=false`: разбор снова внутри запроса ленты |
