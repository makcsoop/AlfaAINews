# Архитектура

Значимость считает код, LLM разбирают и объясняют. Разбор — один раз на «сюжет × отрасль × версия сюжета», кешируется.
Под клиента: вклад канала = направление фактора × чувствительность клиента со знаком.

## Подготовка (один раз)
- **A. Реестр позиций ЦМИ (Р1).** 9 обзоров → атомарные позиции: тезис, прогноз с числом, канал, дата, страница, цитата, срок актуальности. Kimi-K2.6, цитата сверяется с PDF кодом. Поиск BM25 + pgvector, слияние RRF (k=60).
- **B. Профиль клиента (Р2, граф — Р1).** ОКВЭД → 30 каналов по `channels_matrix.yaml`. Продукты дают знак: кредит/лизинг → ставка −, депозиты → ставка +, ВЭД → курс/санкции/логистика, зарплатный проект → рынок труда. Граф платежей: топ-контрагенты, их ОКВЭД, доли, HHI; группа по GROUP_ID и связям через физлиц; ранг выручки в классе ОКВЭД; полнота профиля.
- **C. Знания аналитиков рынка (Р1).** Архив 14 370 постов 21 канала, фильтр кодом → Gemma 4: механизмы «событие → канал → отрасль», ожидания перед плановыми событиями, разборы после события. Агрегация с весом канала, поправка на односторонность (85%+ «покупать» → ×0,5). Приор только при ≥ 5 независимых каналах. Поле `origin`.

## Поток новостей
1. **Сбор (Р1).** RSS: ПРАЙМ `/export/rss2/index.xml`, Интерфакс, РБК (полный текст в ленте), ТАСС, Коммерсантъ, Ведомости, ЦБ RssPress; trafilatura; ETag; 1 rps на хост. Telegram: Telethon по числовым id, t.me/s — запасной путь. Реестр источников: уровень 0–3, стартовый вес.
2. **Отсев и склейка (Р1).** Словарь отсева с причиной в журнале. SimHash (≤ 3) — копии. USER-bge-m3 + общая сущность + тип события, окно 72 ч, сравнение с сюжетом целиком. Официальный источник или 2 независимых уровня 1 → «подтверждено».
3. **Экстрактор (Р1).** Natasha + словари → Gemma 4, строгий JSON, у каждого поля цитата; код проверяет цитату (rapidfuzz ≥ 90) и числа.
4. **Версии сюжета (Р1).** Повторный разбор только при существенном изменении: официальное подтверждение, новые числа, смена знака.
5. **Сопоставление и скоринг v0 (Р2).** `score = quality × freshness × (Σ вкладов каналов + прямые совпадения + сюрприз)`. Сюрприз — к прогнозу ЦМИ и к консенсусу рынка. Три главных вклада → «почему вы это видите».
6. **Быстрая карточка (Р2).** Без LLM: факты с цитатами, статус, вклады, ближайшая позиция банка.

## Глубокий разбор (топ-K пар «сюжет × отрасль»)
7. **Планировщик (Р3, GLM-5.3-Flash).** Шаблон по типу события, LLM достраивает при пробелах, ≤ 8 шагов, досье с id.
8. **Аналитики.** Бизнес (Р3, Qwen3.6) и финансы (Р3, GLM-5.3) параллельно, не видят друг друга, выдают направление/силу/горизонт по всем каналам со ссылками на досье. «Банк и рынок» (Р1, код) и «Статистик» (Р1, код).
9. **Критик (Р3).** Код: числа и даты в цитатах, ссылки, метки, 6 вопросов ТЗ, ≥ 2 признака компании, нет «банк ожидает» вне раздела банка. Провал → задача планировщику, ≤ 2 круга.
10. **Арбитр (Р3, код).** Противоположное направление по общему каналу при силе ≥ средней → «на проверке» + список спорных. Не блокирует выдачу.
11. **Скоринг значимости (Р2).** Та же формула, влияние по каналам из разбора. Уверенность high/medium/low с причинами.

## На клиента
12. **Карточка (Р3, Qwen3.6).** Текст по 6 вопросам ТЗ + «что изменит вывод» + «рынок ждал / банк ждал / вышло». Акценты по роли. 5 меток. «Предложение банка» только по продуктовому триггеру.
13. **Финальная проверка карточки (Р3, код).** Ссылки существуют, числа есть в источниках, bank_view → только ЦМИ, market_view → только пост. Провал → 1 перегенерация → шаблон.
14. **Лента и UI (Р2), вопрос-ответ (Р3, DeepSeek-V4.1-Flash).** Виджет «Важно для вашего бизнеса», переключатель роли, трасса разбора.
15. **Обратная связь (Р2).** Только явные оценки в обучение (вес 0,3), клики — в метрики. nDCG@5, precision@5, пропуски по покрытым/непокрытым отраслям.
