# Экстрактор: Gemma 4 или Qwen3.6

22.10.2026, 10 экономических сюжетов (по одному на тип события), `scripts/compare_extract_models.py`,
сырые цифры — `docs/model_comparison.json`. Каждое поле ответа модели проверяется кодом: цитата есть
в тексте (rapidfuzz ≥ 90), число есть в цитате; непроверенное отбрасывается, один повторный запрос.

**Выбор: Gemma 4 26B A4B — основная, Qwen3.6 35B A3B — запасная** (как в финальной архитектуре).

| | Gemma 4 | Qwen3.6 |
|---|---|---|
| Валидный JSON | 13 / 13 | 14 / 14 |
| Полей отброшено проверкой | 2 | 2 |
| Проверенных чисел добавлено к правилам | 21 | 24 |
| Факторов с цитатой | 11 | 19 |
| Смен типа события относительно правил | 2, обе верные | 5, из них 3 ошибочные |
| Токены вход / выход | 14 978 / 7 702 | 15 386 / 9 012 |
| Стоимость, поле `usage.cost` API | 0,38 | 1,13 |
| Время на 10 сюжетов | 129 с | 124 с |

Ошибочные смены типа у Qwen: ограничения на импорт → «принятое регулирование», договорённость «Газпрома»
с CNPC → «принятое регулирование», «тарифный коридор» в страховании → «пошлина».

## Что важно для LLM-клиента (Разработчик 3)

- **У Qwen3.6 нужно выключать рассуждения**: `"reasoning": {"enabled": false}`. Без этого модель тратит
  весь `max_tokens` на рассуждения и не возвращает JSON (0 из 10 в первом прогоне при 1500 токенах).
- API возвращает стоимость запроса в `usage.cost` — её удобно суммировать в менеджере бюджета.
- `response_format: {"type": "json_object"}` поддерживается; Gemma и Qwen отдают чистый JSON.
- Временный адаптер — `backend/extract/llm_adapter.py`; когда появится клиент, экстрактор переключается на него
  через порт `JsonLLM` без правок логики.
