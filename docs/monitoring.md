# Мониторинг качества и обратная связь

Что измеряем, как часто, какие пороги считаем тревожными, кто смотрит и чем считать. Три слоя: контент
(правдивы ли карточки), персонализация (тем ли клиентам и в том ли порядке), AI-компоненты (как работают модели
и во что обходятся). Плюс два канала обратной связи: пользователи в интерфейсе и эксперты-разметчики.

Связанные документы: [масштабирование и сопровождение](scaling_and_ops.md), [безопасность](security.md),
[разметка](../eval/README.md).

## Обратная связь пользователей

В карточке три кнопки (`frontend/src/components/FeedbackBar.tsx` → `POST /feedback`, таблица `feedback`):

| Кнопка | `kind` | Что делает |
|---|---|---|
| Полезно | `useful` | поднимает похожие сюжеты (тот же тип и главный фактор) в ленте этой компании |
| Не про нас | `not_relevant` | опускает похожие сюжеты; вес отметки 0,3, потолок 0,6 (`config/scoring.yaml`, `feed`) |
| Неверно? | `wrong` | порядок ленты **не меняет**: сигнал качества разбора, в очередь проверки аналитику |

Клики по источникам (`click_source`) идут только в метрики. Отметки персонализируют ленту только своей
компании; общие правки (матрица каналов, веса) делаются людьми по недельной сводке, а не автоматически.

Запросы к таблице `feedback` для недельной сводки:

```sql
-- доля «не про нас» по типу события за 7 дней
SELECT s.event_type,
       avg((f.kind = 'not_relevant')::int) AS not_relevant_share, count(*) AS marks
FROM feedback f JOIN stories s ON s.id = f.data->>'story_id'
WHERE f.kind IN ('useful', 'not_relevant') AND f.at > now() - interval '7 days'
GROUP BY 1 ORDER BY 2 DESC;

-- отметки «Неверно?» за сутки — разобрать вручную
SELECT card_id, data->>'company_id' AS company, data->>'claim_id' AS claim, at
FROM feedback WHERE kind = 'wrong' AND at > now() - interval '1 day' ORDER BY at;
```

## Обратная связь экспертов: разметка

Процесс ([`eval/README.md`](../eval/README.md)):

1. `uv run python eval/labeling/make_pairs.py --batch <партия> --labelers <имена>` — пары «сюжет × компания»
   отбором пулом (топ системы, топ бейзлайна, случайные) и Excel разметчикам. Разметка вслепую: оценок системы
   в файле нет.
2. Разметчик ставит значимость 0–3, главный канал и знак (ТЗ — в документе для разметчика).
3. `uv run python eval/labeling/import_labels.py <файлы> --db` — проверка файлов, CSV меток, согласие и метрики.

Пересклейка сюжетов меняет их id. В CSV меток есть колонка `item_ids` (материалы сюжета на момент разметки):
метрики перепривязывают пару к сюжету, где сейчас эти материалы, и пишут в отчёте, сколько пар найдено,
перепривязано и потеряно. Для партий без этой колонки — `eval/labeling/relink_items.py`.

### Текущее состояние (25.10)

Одна партия `oct-60`: 60 пар, 6 компаний кейса, один эксперт. На живой базе 25.10 нашлись **43 пары из 60**
(32 по своему сюжету, 11 перепривязаны по материалам, 17 потеряны — их сюжеты вышли из окна склейки живой
базы). На этих 43 парах (`reports/metrics.md`):

| Метрика | Система | Бейзлайн |
|---|---|---|
| nDCG@5 | 0,548 | 0,690 |
| precision@5 | 0,133 | 0,133 |

**Система на этой разметке не лучше бейзлайна.** Причины, которые видны сейчас:

- у метрики почти нет диапазона: важных пар 7 из 60, около одной на клиента, потолок precision@5 — 0,133;
  precision@5 на такой разметке систему от бейзлайна не отличает;
- разметка — мнение одного человека, согласие не посчитать;
- 24.10 по этой же разметке были исправлены ошибки скоринга (передача «нефть → топливо», подотрасли,
  подсказки направления), но после пересклейки часть пар сменила состав материалов.

Что нужно, чтобы цифра стала надёжной: следующая партия — 6 клиентов × 15 пар, хотя бы 3 важных пары на клиента
(добавить в пул сюжеты с высокой оценкой по профилю), два разметчика и 10 общих пар для согласия.

## Что пока не автоматизировано

- Расчёт метрик и отчётов запускается вручную по таблице выше: планировщика и CI нет.
- Метрики AI-компонентов во времени не накапливаются: `reports/budget.md` и `reports/quality.md` —
  снимки на момент запуска. Ближайший шаг — эндпоинт `GET /metrics/ai` по журналу вызовов и трассам за день.
- Кнопка «Неверно?» отмечает карточку целиком; выбор конкретного утверждения (`claim_id`) API принимает,
  интерфейс пока не передаёт.
