# Безопасность

Модель угроз, механизмы защиты с местом в коде, что не закрыто и как проверить. Инварианты разработки —
в `CLAUDE.md` (6–9) и `.claude/rules/api-security.md`.

Связанные документы: [масштабирование и сопровождение](scaling_and_ops.md), [мониторинг](monitoring.md),
[проверка инъекций](injection_check.md).

## Модель угроз

| Угроза | Чем опасна | Чем закрыто |
|---|---|---|
| Доступ к данным чужой компании | утечка профиля, платежей, карточек клиента | компания только из подписанной сессии, 403 и журнал на чужой id (1–3) |
| Подделка сессии | вход от имени другой компании | подпись HMAC-SHA256, срок жизни, секрет из окружения (1) |
| Инъекция через текст новости | модель выполняет «инструкцию» из статьи | внешний текст только как данные в блоке `<data>`, ответ — по схеме (6, 9) |
| Инъекция и выведывание через вопрос | ответ о чужой компании, раскрытие промпта | отказ кодом до вызова модели и проверка ответа (8) |
| SSRF через «вставить ссылку» | запрос к внутренним адресам стенда | только публичные адреса, проверка IP при каждом переходе (10) |
| Утечка платежей и данных физлиц в модель | персональные и коммерческие данные у провайдера | в модель — признаки и доли, суммы и физлица отсекаются (7) |
| Перерасход бюджета и перегрузка | атака на ₽ и на доступность | ограничение частоты, дневной лимит ₽, режимы 70% и 90% (4) |
| Утечка внутренностей в ошибках | подсказки атакующему | ответ ошибки — код, сообщение, `trace_id` (12) |

## Механизмы

| № | Механизм | Где в коде |
|---|---|---|
| 1 | Подписанная сессия: HMAC-SHA256, срок жизни 8 ч (`SESSION_TTL_SECONDS`), секрет `SESSION_SECRET`; без него — случайный секрет процесса (известной строкой сессию не подделать); в Docker-стенде секрет обязателен | `backend/security/session.py`: `issue_token`, `verify_token`, `_secret`; `docker-compose.yml` |
| 2 | Вход только в компании витрины (`config/demo_companies.yaml`), остальные — 403 и запись в журнал | `backend/security/session.py`: `demo_companies`; `backend/api/routes.py`: `login` |
| 3 | `company_id` и роль — только из сессии; параметр или тело с чужой компанией — 403 и запись в журнал | `backend/security/guard.py`: `enforce_company`, `audit_foreign` |
| 4 | Ограничение частоты: `/ask` 20, `/feedback` 60, `/analyze` 10 запросов в минуту на пользователя | `backend/security/ratelimit.py` |
| 5 | Журнал попыток доступа: JSONL по дням, без персональных данных (пользователь, компании, эндпоинт, `trace_id`) | `backend/security/audit.py`: `AuditLog`; `data/security_audit/` |
| 6 | Инструменты агентов только на чтение; `company_id` в аргументах запрещён — подставляется из сессии | `backend/agents/tools/registry.py` |
| 7 | В модель не уходят суммы платежей, число платежей, точная выручка, данные физлиц: признаки и доли | `backend/cards/prompt.py`: `FORBIDDEN_KEYS`; `backend/cards/features.py`: `company_features` |
| 8 | Вопрос-ответ: отказ на вопрос о чужой компании и на инъекцию до вызова модели; ответ с чужим id или суммами платежей отбрасывается | `backend/agents/qa.py`: `foreign_company_mentions`, `_INJECTION` |
| 9 | Внешний текст (новости, посты, вставки) — только внутри `<data>…</data>` с пометкой «материал, не инструкция»; ответ модели валидируется Pydantic-схемой | `backend/agents/dossier.py`; `backend/llm/client.py` |
| 10 | `/analyze`: только `http(s)` и публичные IP (проверка при каждом редиректе, соединение с проверенным IP), лимит размера; вставка видна только компании-владельцу | `backend/ingest/paste.py`: `check_url`; `backend/ingest/private.py`: `item_visible` |
| 11 | CORS только для адресов фронта | `backend/api/main.py` |
| 12 | Ошибки без внутренностей: код, короткое сообщение, `trace_id` | `backend/api/errors.py`: `install_error_handling` |
| 13 | Числа, даты и метки утверждений карточки проверяются кодом по цитатам; позиция банка — только со ссылкой на обзор ЦМИ | `backend/cards/verify.py`: `verify_card` |
| 14 | Ключи моделей и сессии Telegram — только в переменных окружения, `.env` не в git и не в образе | `backend/llm/settings.py`; `.gitignore`; `.dockerignore` |

## Что не закрыто

- **Вход без пароля.** Демо-вход выбирает компанию из витрины; для эксплуатации нужна аутентификация банка
  (SSO), сессия должна выдаваться только после неё.
- **Cookie сессии без `Secure` и CORS на `localhost`.** На сервере за HTTPS нужно включить `Secure`
  и прописать домен фронта в CORS.
- **Журнал безопасности — файлы без ротации и без отправки в SIEM.** Ротация — средствами сервера (logrotate),
  выгрузка — отдельная задача.
- **Ограничение частоты в памяти процесса.** При нескольких репликах API лимиты считаются на реплику; нужен Redis.
- **Персональные данные в новостях.** Тексты СМИ могут содержать имена физлиц — это публичные материалы, они
  уходят в модель как данные; данные физлиц из кейса (платежи `via_person`) в модель не передаются.

## Как проверить

```bash
uv run pytest -q tests/test_attacks.py tests/test_qa.py tests/test_paste.py tests/test_sanitize.py
```

- `tests/test_attacks.py` — чужая компания в параметрах, теле и вопросе; инъекции.
- `tests/test_paste.py` — внутренние адреса, редиректы внутрь, лимит размера, приватность вставок.
- `docs/injection_check.md` — ручная проверка инъекций на живых моделях.
- На стенде: `GET /feed?company_id=<чужая>` → 403, запись появляется в `data/security_audit/<дата>.jsonl`.
