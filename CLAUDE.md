# News Insights — персональная новостная аналитика для Альфа-Бизнеса

Хакатон Альфа-Банка, 5 рабочих дней, 3 разработчика. Сервис превращает поток новостей и аналитику ЦМИ Альфа-Банка
в персональные карточки для ЛПР крупного бизнеса: что произошло, почему важно именно этой компании, что делать.

Главная идея: **значимость считает код (скоринг), LLM только разбирают событие и пишут текст.**
Сюжет разбирается один раз на пару «сюжет × отрасль», под клиента и роль знак и вклад каждого канала подставляет код.

Подробности — не грузи без нужды, читай по ссылке, когда задача их касается:
- архитектура и этапы: `docs/architecture.md`
- схемы данных и пример карточки: `docs/contracts.md`
- задачи по дням: `docs/tasks/dev1.md`, `dev2.md`, `dev3.md`
- статус передач между разработчиками: `docs/HANDOFFS.md`

## Инварианты (нарушать нельзя)

1. Все вызовы LLM — только через `backend/llm/client.py` (бюджет, журнал, запасная модель). Никаких прямых HTTP к провайдеру.
2. Разрешены только модели: Gemma 4 26B A4B, GLM-5.3-Flash, Qwen3.6 35B A3B, DeepSeek-V4.1-Flash, Qwen3-VL-30B-A3B, Kimi-K2.6. Лимит 500 ₽/день на общий ключ.
3. Каждый ответ LLM валидируется Pydantic-схемой; невалидный — один повтор, потом запасная модель, потом шаблон.
4. Каждое утверждение в карточке имеет `kind` (fact / bank_view / market_view / model_inference / bank_offer) и `refs`. Числа и даты проверяются кодом по цитате.
5. Аналитики выдают **направление фактора** (ставка ↑, рубль ↑), а не «хорошо/плохо». Знак для клиента ставит только скоринг (Р2).
6. `company_id` берётся из сессии, никогда из текста запроса или ответа модели. Инструменты агентов только на чтение.
7. Текст новостей и постов передаётся модели только как данные в отдельном блоке, не как инструкции.
8. В модель уходят признаки и доли, не сырые платежи и не данные физлиц.
9. Ключи и сессии Telethon — только в переменных окружения. Не читать `.env`.
10. Знания аналитиков используются только опубликованные раньше даты сюжета; у каждого знания поле `origin`.

## Стек и команды

- Python 3.12, uv, FastAPI, Pydantic v2, PostgreSQL + pgvector, Redis, APScheduler; React + Vite во `frontend/`.
- NLP: Natasha, rapidfuzz, sentence-transformers (`deepvk/USER-bge-m3`), trafilatura, feedparser, Telethon.
- Запуск: `docker compose up -d` · тесты: `uv run pytest -q` · линт: `uv run ruff check . --fix` · типы: `uv run mypy newsai`
- Фронт: `cd frontend && npm run dev` · сборка `npm run build`
- Тесты не вызывают настоящие модели: LLM-клиент в тестах в режиме `LLM_MODE=fixture`.

## Как работать

- Одна задача — одна сессия. Перед новой несвязанной задачей `/clear`.
- Для задачи больше одного файла — сначала план (plan mode), потом код.
- Сначала тест на фикстуре `fixtures/rate_14/bundle.json` («ЦБ сохранил ставку 14%»), потом код, потом прогон теста.
- Пиши маленькими шагами: файл → тест → следующий файл.
- Не читай большие CSV и PDF целиком: смотри `head`, схему колонок или поручи агенту `data-profiler`.
- Тяжёлые прогоны тестов и логи — через агента `test-runner`, в основной контекст только итог.
- После завершения задачи: отметь пункт в `docs/tasks/devN.md`, при передаче — строку в `docs/HANDOFFS.md`.
- Коммиты: `feat(зона): что сделано`; `main` всегда запускается.
